# Пользовательские сценарии — ручная проверка системы «с нуля»

Чек-лист для ручного прогона глазами/руками (не автотесты). Каждый шаг — «Действие → Ожидаемый результат». Ставьте `[x]` по ходу, невыполнившиеся пункты помечайте `❌` и коротко описывайте, что пошло не так.

**Окружение:** http://localhost:5173 (frontend), backend на 8011, БД — dev-Postgres на 5433 (тестовые данные, чистить безопасно).

**Перед стартом** заведите (или убедитесь, что уже есть) три тестовых аккаунта — без них разделы 4 и 5 не пройти:
- 1 администратор (обычно уже есть — `admin`)
- 1 менеджер, например `test_manager`
- 1 наблюдатель, например `test_observer`

## 3. Полный жизненный цикл заказа (сквозной сценарий, под админом или менеджером)

Цель — пройти путь заказа от создания до завершения одним прогоном.

| Шаг | Ожидаемый результат |
|---|---|
| [ ] «Заказы» → «Создать заказ» → выбрать клиента, валюту (например USD), детали — сохранить | Заказ создан, номер вида `{код_клиента}-{n}`, статус «В работе» |
| [ ] (только под админом) в модалке создания выбрать конкретного менеджера, не себя | Заказ создаётся с указанным менеджером |
| [ ] Открыть карточку заказа | Видны вкладки: Товары, Запросы на оплату, Логистика, ДиР, и блок «Заметки» ниже |
| [ ] Вкладка «Товары» → «+ Добавить» → указать поставщика, наименование, количество > 0, цену | Товар появляется в таблице, футер показывает «Итого {валюта}» |
| [ ] Добавить товар с ценой `0` | Принимается (цена может быть нулевой — это не баг) |
| [ ] Добавить товар с количеством `0` | Отклоняется валидацией |
| [ ] Добавить товар с именем из одних пробелов `"   "` | Должно отклоняться — если создался, это баг (см. известные проблемы ниже) |
| [ ] Вкладка «Запросы на оплату» → «Создать запрос» → отметить товар(ы), сумма подставляется автоматически (остаток к выставлению), указать «Реквизиты» | Запрос создан, статус остатка виден в списке заказов (прогресс-бар оплаты) |
| [ ] Попробовать создать запрос с пустыми реквизитами | Кнопка сохранения неактивна |
| [ ] Открыть созданный запрос → «Внести оплату» → сумма и курс | Остаток запроса уменьшается на `сумма ÷ курс` (курс вводится как «1 <валюта запроса> = X <валюта оплаты>») |
| [ ] Попробовать внести оплату больше остатка | `422 Payment amount (...) exceeds remaining balance (...)` — текст ошибки будет на английском, это норма для всей системы |
| [ ] Внести оплату ровно на остаток | Остаток становится 0, форма «Внести оплату» пропадает (её показывают только пока остаток > 0) |
| [ ] Вкладка «Логистика» → добавить отправку по товару: количество ≤ остатка к отправке, дата отправки | Запись создаётся со статусом «В дороге» |
| [ ] Добавить комментарий к логистике | Появляется в истории комментариев |
| [ ] (админ) «Принять» логистику — указать дату получения, расход, валюту, курс | Статус меняется на «Принят», расход попадёт в расчёт прибыли |
| [ ] (админ) «Распринять» ту же запись | Возвращается в «В дороге», данные приёмки (дата/расход/курс) очищаются |
| [ ] Вкладка «ДиР» → «+ Добавить доход» | Строка дохода появляется, футер показывает сумму по валюте |
| [ ] «+ Добавить расход» | Аналогично для расхода |
| [ ] Проверить блок прибыли над вкладками | Если логистика ещё «В дороге» — баннер «Итоги посчитаются после приёмки всей логистики»; после приёмки — считает Доходы − Закупки − Логистика − Расходы = Чистая прибыль, %, дни в обработке |
| [ ] Блок «Заметки» → добавить заметку | Появляется сразу (оптимистично), остаётся после обновления страницы |
| [ ] (админ) «Завершить» заказ, когда логистика ещё «В дороге» или остаток по запросу не нулевой | `409 Cannot complete...` — завершение блокируется |
| [ ] Довести логистику до «Принято» и остатки запросов до 0, затем «Завершить» | Заказ переходит в «Завершён» |
| [ ] Попробовать добавить товар / логистику / запрос / ДиР-запись к завершённому заказу | `409 Order is completed...` — всё заблокировано для любой роли |
| [ ] Добавить заметку к завершённому заказу | Заметки — исключение, добавляются даже на завершённый заказ |
| [ ] (админ) «Вернуть в работу» | Статус снова «В работе», `completed_at` очищается, редактирование разблокируется |
| [ ] «Отменить» заказ в работе | Статус «Отменён» |
| [ ] Попробовать «Отменить» уже завершённый заказ | Запрещено всегда (`409`) — только через «Вернуть в работу», затем отдельно отменить |
| [ ] (админ) «Вернуть в работу» отменённый заказ | Возвращается в «В работе» |
| [ ] (админ) Удалить заказ, у которого есть товары/логистика/запросы/ДиР | `409 Order has N related record(s)...` |
| [ ] Создать пустой заказ без единой вложенной сущности и удалить его | Удаляется без ошибок |

## Известные особенности — не репортить как баги

- Текст ошибок в UI (красные баннеры/тосты) приходит от backend на английском, даже если весь остальной интерфейс на русском.
- Rate-limit на логин сбрасывается при перезапуске backend-контейнера (хранится в памяти).
- Cookie сессии не отзывается на сервере при logout — если у вас утёк токен, «выход» его не аннулирует до истечения 7 дней (это архитектурное ограничение, не баг конкретной кнопки).
- Пикер телеграм-групп для клиентов с 2+ группами не реализован в интерфейсе создания запроса на оплату / уведомления о получении — упомянуто в разделе 7.
- Панель товара показывает «Отправлено 0 / qty» как статичный текст, не отражающий реальное количество из логистики — известная визуальная недоработка, не пересчитывайте вручную, чтобы понять, баг ли это.
