## Сводка: на что смотреть в первую очередь

1. **❌ Отменённый заказ не «застывает»** (§13, §6). `get_order_for_write` блокирует правки только для статуса `completed`. В отменённый заказ можно добавлять товары, логистику, оплаты и записи ДиР; `PATCH /api/orders/{id}` (детали, менеджер) не заблокирован ни для отменённого, ни для завершённого. ТЗ §13: «Заказ „застывает“, даже админ меняет только статус».
2. **❌ Глобальный эндпоинт оплаты обходит контроль остатков** (§8). `POST /api/payment-requests/{id}/payments` (`routers/payment_requests_global.py:110`) создаёт платёж без проверки остатка по запросу и без блокировки завершённого заказа — в отличие от `POST /api/orders/{id}/payment-requests/{id}/payments`, где проверка есть. Фронтенд его не вызывает (`api/paymentRequestsGlobal.ts:42` — мёртвый код), но эндпоинт открыт любому менеджеру.
3. **❌ Скачивание файла не проверяет права на заказ** (§17). `GET /api/files/{file_key}` (`routers/files.py:72`) требует только аутентификацию. Менеджер чужого заказа скачает любой файл по ключу. У `DELETE` такая проверка есть (`_find_file_order_id`), у `GET` — нет. Ключи — случайные UUID, это единственная защита.
4. **❌ В списке заказов нет фильтра по менеджеру** (§5). Бэкенд (`orders.py:115`) и api-клиент (`api/orders.ts:69`) параметр поддерживают, но `OrdersPage.tsx` его не отображает. На сводных страницах «Логистика» и «Запросы на оплату» фильтр есть.
5. **⚠️ «Оплачено» и «остаток» на карточке заказа смешивают валюты.** `get_orders_payment_totals` складывает суммы всех запросов заказа, каждая из которых уже приведена к валюте *своего* запроса, без досчёта до валюты заказа. Карточка при этом подписывает результат валютой заказа. Раньше это было теоретической проблемой, после фичи «товары в любой валюте» — реальной.
