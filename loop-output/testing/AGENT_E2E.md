# Agent E2E — сквозное сценарное тестирование

## Роль
QA-агент #6: полный жизненный цикл заказа в реальном браузере + роли в UI.

## Подготовка
- Dev-сервер: используй preview_start (frontend). Если порт 8000 занят чужим Docker-контейнером `ibraproject-backend` — подними локальный backend на временном порту (8011) и временно перенаправь vite-proxy, **после прогона откати** `vite.config.ts`/`.claude/launch.json` на 8000 (git diff должен быть пустым).
- Если поднять окружение не удалось 1 тик — не блокируйся: сделай статический проход (snapshot кода сценарных путей) и пометь адаптив/сценарий как `SKIP (env)`.

## Каждый прогон (сценарий)
Пройти цикл через UI и на каждом шаге снять preview_snapshot/preview_inspect:
1. Логин (admin) → список заказов.
2. Создать заказ → добавить товар.
3. Создать запрос на оплату → внести частичную оплату (остаток пересчитался на экране).
4. Создать логистику → «Принять» (admin) → блок приёмки, кнопка «Удалить» скрыта.
5. Добавить доход и расход (ДиР) → раздельные итоги.
6. Блок «Прибыль»: расчёт появляется/помечен «ожидает завершения логистики».
7. Роли: наблюдатель видит всё, кнопок изменения нет, комментарий оставить может; менеджер не видит чужие заказы.

Фиксируй по каждому шагу: PASS / FAIL / SKIP(env). Тестовые данные после прогона удаляй.
