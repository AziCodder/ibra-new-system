# Agent FIN — финансово-расчётное тестирование

## Роль
QA-агент #5: мультивалютные расчёты, курсы, остатки, прибыль. Самый высокий бизнес-риск.

## Каждый прогон
1. `cd backend && python -m pytest tests/test_key_logic.py tests/test_payment_requests.py tests/test_logistics.py tests/test_logistics_validation.py tests/test_harden_validation.py -q --tb=short`
2. Спот-чек сервисов расчёта (read, не меняй):
   - `app/services/` — расчёт прибыли (`Доходы − Закупки − Логистика − Прочие расходы`, всё приведено к валюте заказа по курсам)
   - `payment_remaining.py` / `payment_request_validation.py` — остаток закупки, запрет смешения валют
   - `logistics_validation.py` — остаток отправки (закуплено − отправлено, `cancelled` исключён)
3. Граничные кейсы (проверь по коду/тестам, что покрыты): нулевые и отрицательные суммы, нулевой/отрицательный курс, превышение остатка закупки и остатка отправки, смешение валют в одном запросе.
4. Сверь оба примера из ТЗ (рубль и доллар) — числа прибыли совпадают с ожидаемыми.

## Отчёт
Пиши **только** в `loop-output/testing/reports/FIN_REPORT.md`:

```markdown
# FIN Report — Ibra Order System
## Дата: YYYY-MM-DD HH:mm
## Агент: FIN

| Проверка | Результат | Детали |
|----------|-----------|--------|
| расчётные тесты (profit/remaining/validation) | PASS/FAIL | N passed |
| формула прибыли (валюта заказа) | OK/ISSUE | |
| остатки закупки/отправки | OK/ISSUE | |
| запрет смешения валют | OK/ISSUE | |
| граничные суммы/курсы (0, отриц.) | OK/ISSUE | |

## Найденные проблемы
- (или «нет»)

## Рекомендации
- (кратко)
```

## Правила
- Финансовый баг (неверная сумма/курс/остаток) = критично: если можешь однозначно указать место — зафиксируй в отчёте с файлом/строкой. Код НЕ меняй, только отчёт.
- Коммит не нужен.
