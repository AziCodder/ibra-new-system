## 3. Найденное (ни одно не блокер)

### 3.1 Observer не может добавлять заметки — трактовка ТЗ §9 (MINOR, product-решение)
Флаг подтверждён тремя агентами (SEC, UX, E2E). Реализация согласована BE+FE: `notes.py:26` → 403, `NotesSection.tsx:87` скрывает форму. Но ТЗ §9 («наблюдатель может оставлять комментарии») можно прочитать как «должен мочь и заметки».
→ **Это не баг, а решение по продукту.** Нужно определиться: заметки заказа = комментарии (тогда открыть observer) или отдельная сущность (тогда всё верно). Важно: комментарии к **логистике** для observer уже открыты — так что доступ к обсуждению у него есть.

### 3.2 Рассинхрон dev docker-compose ↔ vite proxy (WARN, dev-ергономика)
`docker-compose.yml:23` публикует backend на `8000:8000`, а `vite.config.ts:10` проксирует на `localhost:8011`.
→ Уточнение к рекомендации агентов: правки «8000→8011» **недостаточно** — докеризованный frontend всё равно проксирует на *свой* `localhost`, а не на backend-контейнер. Рабочих режима два, и путаница между ними: (а) **host-dev** — backend в docker на :8011 + `npm run dev` на хосте (это то, что реально запущено и работает); (б) **full-compose** — тогда прокси должен смотреть на `http://backend:8000` (внутренняя сеть). Сейчас настроен только режим (а).
→ **На прод не влияет** (там `docker-compose.prod.yml` + nginx, отдельная конфигурация). Это чисто локальное удобство запуска.
